# Scoring App

試験の採点と成績評価を行うデスクトップアプリです。問題と受験者を登録したら、キーボードだけで次々に点数を入力し、重み付きの最終得点と成績区分の分布をその場で確認できます。

[Rust](https://www.rust-lang.org/) と [Dioxus](https://dioxuslabs.com/) (desktop) で作られており、Windows / macOS / Linux で動作します。

## 主な機能

| 画面 | 内容 |
| --- | --- |
| **採点** | 受験者ごとに各問題の点数を入力します。全受験者の点数と最終得点が一覧表で表示され、一覧表の受験者をクリックするとその受験者の採点に移ります。問題ごとの採点メモ（コメント）も記録できます。満点を超える点数は赤く表示され、保存されません。コメント・点数入力・一覧表の 3 つの区画は、区切り線をドラッグして大きさを変えられます。 |
| **問題設定** | 問題名、満点、重み、コメントを登録します。問題一覧だけを保存・読み込みできます。id を変更すると、その問題の入力済みの点数も新しい id に引き継がれます（重複する id は登録できません）。「Add row」で追加した問題の満点は、設定画面で決めた初期値（最初は 8）になります。 |
| **受験者設定** | 受験者IDと氏名を登録します。CSV ファイルから読み込むこともできます。受験者一覧だけを保存・読み込みできます。「Add row」を押すと、直前の番号に続く番号で行が追加されます（例: `A009` → `A010`）。受験者IDを変更すると、入力済みの点数も引き継がれます（重複する番号は登録できません）。 |
| **成績評価** | 成績区分（例: 優 / 良 / 可 / 不可）の下限点と、割合の目安上限を設定します。区分ごとの人数・割合・累積割合、分布（ヒストグラム）と統計値、受験者ごとの最終得点と区分の一覧を表示し、CSV にエクスポートします（下記）。成績区分だけを保存・読み込みできます。 |
| **設定** | 新しい問題の満点の初期値、採点画面のレイアウト、キー割り当てを変更します。設定は自動で保存され、どの採点ファイルでも共通です。 |

### 最終得点の計算方法

```
最終得点 = Σ (得点 / 満点 × 重み) / Σ 重み × 100
```

最終得点は 0〜100 点（小数点以下は四捨五入）です。未入力の問題が 1 つでもある受験者は計算と集計から除かれます。要再採点の点数がある受験者も集計から除かれます（下記）。どの区分の下限点にも届かない受験者は、成績評価画面で「（区分なし）」として数えられます。

### 要再採点

点数を入力したあとでその問題の満点を変更すると、その点数は「要再採点」になり、採点画面の一覧表と受験者欄に ⚠ が表示されます（例: 「満点 5→8」）。満点を採点時の値に戻すと、表示は消えます。

- 点数を入力し直すと、その時点の満点で採点したものとして扱われます。
- 点数を変えなくてよい場合は、その問題の「確認済み」ボタン（または点数入力欄で `Ctrl+Enter`）を押します。満点を超える点数は確認済みにできません。
- 要再採点の点数がある受験者は、Completed の人数と成績評価の集計に含まれません。
- `Ctrl+Shift+L` で、次の要再採点の受験者に移動できます。

## キーボード操作

キー割り当ては「設定」画面で変更できます。以下は初期値です。`Ctrl` を使うショートカットは、どの入力欄にカーソルがあっても使えます（macOS では `Ctrl` の代わりに `⌘`）。

| キー | 動作 |
| --- | --- |
| `Ctrl+S` | 上書き保存 |
| `Ctrl+Shift+S` | 名前を付けて保存 |
| `Ctrl+O` | ファイルを開く |
| `Ctrl+1` 〜 `Ctrl+5` | 問題設定 / 受験者設定 / 採点 / 成績評価 / 設定 画面へ |
| `Ctrl+F` | 受験者検索を開く（受験者ID・氏名で検索） |
| `Ctrl+J` / `Ctrl+L` | 前の受験者 / 次の受験者（採点画面） |
| `Ctrl+Shift+L` | 次の要再採点の受験者へ |
| `Ctrl+E` | 点数入力欄とコメント欄を行き来する（採点画面。コメント欄では `Esc` でも戻れます） |

採点画面の点数入力欄では、次のキーも使えます。

| キー | テンキー | 動作 |
| --- | --- | --- |
| `Enter` / `↓` | `Enter` / `+` | 次の問題へ |
| `↑` | `-` | 前の問題へ |
| | `/` / `*` | 前の受験者 / 次の受験者 |
| | `.` | 受験者検索を開く |
| `Ctrl+Enter` | | 要再採点の点数を確認済みにする |

検索ウィンドウでは `↑` / `↓` で候補を選び、`Enter` で確定、`Esc` で閉じます。採点画面の下の一覧表で受験者IDか氏名をクリックすると、その受験者の採点に移ります。

### キー割り当ての変更

「設定」画面のキー割り当てで「追加」を押し、割り当てたいキーを押します（`Esc` で取り消し）。1 つの操作に複数のキーを割り当てられます。

- どこでも使える操作には `Ctrl`（`⌘`）を含むキーが必要です。
- `Ctrl+C` / `V` / `X` / `Z` / `Y` / `A` は文字の編集に使うため割り当てられません。点数入力欄の操作には、数字・BackSpace・Delete・Tab・`←` / `→` などの入力用のキーは割り当てられません。
- ほかの操作で使っているキーは割り当てられません（先にそちらから外してください）。

## アプリの設定

「設定」画面の内容は、採点ファイルとは別の `settings.json` に自動で保存され、どの採点ファイルを開いても同じ設定が使われます。設定を変えても、採点ファイルが未保存の状態にはなりません。

| OS | 場所 |
| --- | --- |
| Windows | `%APPDATA%\scoring_app\settings.json` |
| macOS | `~/Library/Application Support/scoring_app/settings.json` |
| Linux | `~/.config/scoring_app/settings.json` |

## データの保存

データはすべて 1 つの JSON ファイルに保存されます。画面右上のボタンで操作します。

- **Save**: いま開いているファイルに上書き保存します（まだファイルがなければ Save as と同じ動作になります）
- **Save as**: 保存先を選んで保存します
- **Load**: JSON ファイルを読み込みます（保存していない変更があるときは確認が表示されます）

保存していない変更があると、ウィンドウのタイトルに `*` が付きます。その状態でウィンドウを閉じようとすると確認ダイアログが表示され、「保存して終了」「保存せずに終了」「キャンセル（終了しない）」を選べます。

### 問題・受験者・成績区分だけの保存と読み込み

「問題設定」「受験者設定」画面と、成績評価画面の「成績区分」にある **保存** / **読み込み** で、それぞれの一覧だけを JSON ファイルでやり取りできます。別の学期や科目で、問題構成・名簿・区分を使い回すときに使います。

- 保存すると、その一覧だけ（例: `{"ratings": [...]}`）を書いたファイルができます。形式は全体の保存ファイルと同じです。
- 読み込みには、全体の保存ファイルも使えます。その一覧だけを取り出して、今の一覧を置き換えます。
- 読み込むファイルにその一覧が含まれていないときは、何も変えずにそう表示します。
- 置き換える前に確認が表示されます。入力済みの点数のうち、対応する問題・受験者がなくなるものがあるときは、その件数も表示されます（点数は消えません。同じ id の問題・受験者を戻せば再び表示されます）。

<details>
<summary>JSON の形式</summary>

```json
{
  "questions": [
    { "id": 1, "name": "問1", "full_score": 10, "weight": 1.0, "comment": "" }
  ],
  "students": [
    { "id": "A001", "name": "山田 太郎" }
  ],
  "scores": [
    { "student_id": "A001", "question_id": 1, "score": 8, "graded_full_score": 10 }
  ],
  "ratings": [
    { "label": "優", "min_score": 80, "max_ratio": 30 },
    { "label": "良", "min_score": 70 },
    { "label": "可", "min_score": 60 },
    { "label": "不可", "min_score": 0 }
  ]
}
```

`max_ratio` は、その区分の割合の目安上限（%）です。超えると成績評価画面に警告が出ます。書かなければ警告しません。

`graded_full_score` は、その点数を入力した（または確認済みにした）ときの満点です。要再採点の判定に使います。これがない点数（以前のバージョンで保存したファイルなど）は、満点を超えていない限り要再採点になりません。

</details>

## CSV から受験者を読み込む

「受験者設定」画面で CSV フォーマットを選び、**Import CSV** を押してファイルを選ぶと、受験者一覧がその内容に置き換わります。点数は受験者IDで結び付いているので、同じ受験者IDの受験者の点数はそのまま残ります。

付属のフォーマットは次のとおりです。見出しの名前はシステムの表示言語やバージョンによって変わることがあるので、合わないときは定義ファイル（下記）を編集してください。

| フォーマット | 対象のファイル | 受験者ID / 氏名の列 |
| --- | --- | --- |
| UTAS | 東京大学 UTAS の履修者名簿（4 行目が見出し行） | `学生証番号` / `氏名` |
| UTOL 課題 | 東京大学 UTOL の課題提出状況 CSV | `[#]学生証番号` / `氏名` |
| 汎用（学籍番号・氏名） | 1 行目が見出しの CSV（Excel で作った名簿など） | `学籍番号` / `氏名` |
| 汎用（student_id・name） | 同じく 1 行目が見出しの CSV | `student_id` / `name` |
| Moodle 成績表 | Moodle の「成績 > エクスポート > プレーンテキストファイル」 | `ID number` / `Surname` + `First name` |
| Moodle 成績表（日本語） | 同じものの日本語表示 | `ID番号` / `姓` + `名` |
| Moodle 評定ワークシート | Moodle の課題「評定ワークシートをダウンロード」 | `Identifier` / `Full name` |
| Canvas 成績表 | Canvas LMS の成績エクスポート CSV | `SIS User ID` / `Student` |
| Blackboard 成績センター | Blackboard Learn の成績表ダウンロード（カンマ区切り） | `Student ID` / `Last Name` + `First Name` |
| WebClass 成績一覧 | WebClass の成績一覧ダウンロード CSV | `ユーザID` / `氏名` |
| OneRoster users.csv | 1EdTech OneRoster v1.1 CSV（教育データ連携の標準形式） | `sourcedId` / `familyName` + `givenName` |

- 受験者IDが空の行と、すでに読み込んだ受験者IDと重複する行は読み飛ばされ、その行番号が画面に表示されます。
- 受験者IDの先頭の `0` は消えません（`01234567` は `01234567` のまま読み込まれます）。
- Moodle 評定ワークシートの受験者IDは参加者番号（`Identifier`）です。同じワークシートに書き戻す（下記）ときはこのまま読み込んでください。
- OneRoster の `users.csv` には教員などの行も含まれます。不要な行は読み込んだあとに「受験者設定」画面で削除してください。

### フォーマットを追加・編集する

フォーマットは Rust のコードではなく JSON ファイルで定義されています。**CSV フォーマット定義...** ボタンを押すと、定義ファイル `csv_formats.json` が入っているフォルダが開きます。このファイルがまだなければ、付属のフォーマットをすべて書き込んだ状態で作成されます。

| OS | 場所 |
| --- | --- |
| Windows | `%APPDATA%\scoring_app\csv_formats.json` |
| macOS | `~/Library/Application Support/scoring_app/csv_formats.json` |
| Linux | `~/.config/scoring_app/csv_formats.json` |

このファイルの中身がフォーマットの一覧です。付属のフォーマットもここに書き出されているので、そのまま編集したり、使わないものを削除したりできます。ファイルはフォーマットの選択欄を開くたびに読み直されるので、編集後にアプリを再起動する必要はありません。

- 同じフォルダの `csv_formats.default.json` は、アプリに付属しているフォーマットの控えです（アプリが上書きするので編集しても残りません）。元に戻したいときや、新しいバージョンで追加されたフォーマットを取り込みたいときに、ここからコピーしてください。
- `csv_formats.json` を削除すると、次にフォーマットを読むときに付属のフォーマットから作り直されます。
- 読み込めない記述（JSON の文法エラーなど）があるときや、使えるフォーマットが 1 つも残っていないときは、画面に理由が表示され、付属のフォーマットが使われます。

```json
[
  {
    "name": "Excel 名簿",
    "description": "1 行目が見出し、Shift_JIS",
    "encoding": "shift_jis",
    "id_header": "受験者ID",
    "name_header": "氏名"
  }
]
```

| 項目 | 既定値 | 内容 |
| --- | --- | --- |
| `name` | （必須） | 選択欄に表示される名前 |
| `description` | `""` | 説明（選択欄にマウスを重ねると表示されます） |
| `encoding` | `"auto"` | `"auto"`（UTF-8 として読めなければ Shift_JIS）、`"utf-8"`、`"shift_jis"` |
| `delimiter` | `","` | 区切り文字（半角 1 文字。タブ区切りなら `"\t"`） |
| `quote` | `"\""` | 囲み文字。`null` にすると囲み文字を使いません |
| `direction` | `"rows"` | `"rows"`: 1 行に 1 人。`"columns"`: 1 列に 1 人（見出しが縦に並ぶ表） |
| `skip_before_header` | `0` | 見出し行の前に読み飛ばす行数（`columns` の場合は列数）。空行は数えません |
| `skip_after_header` | `0` | 見出し行と最初の受験者の間で読み飛ばす行数 |
| `id_header` | （必須） | 受験者IDの列の見出し |
| `name_header` | （必須） | 氏名の列の見出し。`["姓", "名"]` のように並べると、その順に連結します |
| `name_separator` | `" "` | `name_header` を複数指定したときに、間に入れる文字列 |
| `trim_whitespace` | `true` | 各セルの前後の空白（全角スペースを含む）を取り除くか |

## 成績を CSV にエクスポートする

成績評価画面の受験者一覧に、方式ごとに別のフォーマット選択欄とボタンがあります。

| 方式 | ボタン | 動作 |
| --- | --- | --- |
| 新規作成（`new`） | **CSV を作成...** | 指定した列だけの CSV を新しく作ります。受験者一覧の全員が 1 行ずつ並びます。 |
| 既存ファイルに記入（`fill`） | **CSV に記入...** | 他のシステムからダウンロードした CSV を選ぶと、受験者IDで照合して指定した列だけを書き込み、別名で保存します。それ以外の行・列・文字コード・改行はそのまま残ります。 |

付属のフォーマットは次のとおりです。

| フォーマット | 方式 | 内容 |
| --- | --- | --- |
| 成績一覧 | 新規作成 | `id`, `name`, `score`, `rating` の 4 列（UTF-8、BOM 付き） |
| 成績一覧（Shift_JIS） | 新規作成 | 学籍番号・氏名・得点・評語の 4 列を Shift_JIS で |
| 合否一覧 | 新規作成 | 区分を合否（`合` / `否`）に置き換えて書き出す例 |
| Moodle 成績インポート | 新規作成 | Moodle の「成績 > インポート > CSV ファイル」で取り込む CSV |
| WebClass 外部データインポート | 新規作成 | WebClass の「外部データのインポート」用（`user_id`, `score`） |
| manaba 成績登録シート貼り付け用 | 新規作成 | manaba の成績登録シート（Excel）に貼り付けるための CSV |
| OneRoster results.csv | 新規作成 | OneRoster v1.1 の `results.csv`（課題IDと日付の列は空） |
| UTAS | 既存ファイルに記入 | UTAS の履修者名簿の `評語` 列に区分を書き込みます |
| UTOL 課題 | 既存ファイルに記入 | UTOL の課題提出状況 CSV の `評価` 列に最終得点を書き込みます |
| Moodle 評定ワークシート | 既存ファイルに記入 | 評定ワークシートの `Grade` 列に得点を書き込みます（そのままアップロードできます） |
| Canvas 成績表 | 既存ファイルに記入 | Canvas の成績エクスポート CSV の課題列に得点を書き込みます |
| Blackboard 成績センター | 既存ファイルに記入 | Blackboard の成績表ダウンロード CSV の成績列に得点を書き込みます |

- 未完了・要再採点の受験者と、どの区分にも入らない受験者は、点数・区分が空欄になります。その場合は書き出す前に確認が表示されます。
- 既存ファイルに記入する方式では、ファイルにいない受験者と、受験者一覧にいない行の数が、書き出したあとに表示されます。受験者一覧にいない行は変更しません。
- Canvas と Blackboard のフォーマットは、書き込む列の見出し（`header`）が課題ごとに違います。`<課題名>` `<列名>` を実際の見出し（例: `期末試験 (1234567)`）に書き換えてから使ってください。書き換えていないときは、ファイルの見出し一覧がエラーメッセージに表示されます。

### エクスポートのフォーマットを追加・編集する

**定義...** ボタンを押すと、定義ファイル `csv_export_formats.json` が入っているフォルダが開きます（場所と仕組みは `csv_formats.json` と同じで、控えは `csv_export_formats.default.json` です）。付属のフォーマットもこのファイルに書き出されているので、そのまま編集・削除できます。

```json
[
  {
    "name": "成績一覧（Shift_JIS）",
    "encoding": "shift_jis",
    "columns": [
      { "header": "学生証番号", "value": "id" },
      { "header": "氏名", "value": "name" },
      { "header": "評語", "value": "rating" },
      { "header": "合否", "value": "rating", "map": { "不可": "否", "*": "合" } }
    ]
  },
  {
    "name": "UTAS（評語と合否）",
    "mode": "fill",
    "read_as": "UTAS",
    "columns": [
      { "header": "評語", "value": "rating" },
      { "header": "合否", "value": "rating", "map": { "不可": "否", "*": "合" } }
    ]
  }
]
```

| 項目 | 既定値 | 内容 |
| --- | --- | --- |
| `name` | （必須） | 選択欄に表示される名前 |
| `description` | `""` | 説明（選択欄にマウスを重ねると表示されます） |
| `mode` | `"new"` | `"new"`: 新規作成（**CSV を作成...**）、`"fill"`: 既存ファイルに記入（**CSV に記入...**） |
| `read_as` | | `fill` のとき必須。書き込む CSV を読む、取り込み用 CSV フォーマットの名前（見出し行の位置と受験者ID列をこれで決めます） |
| `encoding` | `"utf-8-bom"` | `new` の文字コード。`"utf-8"`、`"utf-8-bom"`、`"shift_jis"`（`fill` は元のファイルと同じになります） |
| `delimiter` | `","` | `new` の区切り文字 |
| `line_ending` | `"crlf"` | `new` の改行。`"crlf"` または `"lf"` |
| `columns` | （必須） | 列の配列（下記） |

`columns` の各要素:

| 項目 | 内容 |
| --- | --- |
| `header` | `new`: 書き出す列の見出し。`fill`: 書き込む列の見出し（元のファイルにある見出し） |
| `value` | `id`、`name`、`score`（最終得点）、`rating`（区分）、`q:<問題id>`（その問題の点数）、`literal:<文字列>`（固定の文字列） |
| `map` | 値の置き換え。まず値と同じキーを探し、なければ `"*"`（空でない値すべて）を使います。空欄を置き換えるときは `""` をキーにします |

## インストール

[Releases](https://github.com/haborite/scoring_app/releases) から、お使いの OS 用のファイルをダウンロードしてください。

| OS | ファイル |
| --- | --- |
| Windows (x64) | `*-setup.exe`（NSIS インストーラ）、`*.msi`、`*_portable.zip`（インストール不要。展開して `grading_app.exe` を実行） |
| macOS (Apple Silicon) | `*.dmg`、`*.app.zip` |
| Linux (x64) | `*.deb`、`*.AppImage` |

> [!NOTE]
> 配布物にはコード署名をしていません。
> - **Windows**: SmartScreen の警告が出たら「詳細情報」→「実行」を選んでください。
> - **macOS**: 「開発元を検証できません」と表示されたら、Finder でアプリを右クリックして「開く」を選ぶか、`xattr -cr /Applications/GradingApp.app` を実行してください。
> - **Linux**: AppImage は `chmod +x` で実行権限を付けてから起動してください。WebKitGTK（`libwebkit2gtk-4.1`）が必要です。

## ソースからビルド

### 必要なもの

- [Rust](https://rustup.rs/)（stable）
- [Node.js](https://nodejs.org/)（Tailwind CSS のビルドに使用）
- [Dioxus CLI](https://dioxuslabs.com/learn/0.7/getting_started/): `cargo binstall dioxus-cli@0.7.3`（または `cargo install dioxus-cli@0.7.3 --locked`）
- Linux のみ:
  ```sh
  sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev libxdo-dev librsvg2-dev
  ```

### 開発

```sh
npm ci
npm run css:watch   # assets/tailwind.css を生成し、変更を監視
dx serve            # 別のターミナルで実行
```

`assets/tailwind.css` は自動生成されるファイルなので、Git では管理していません。ビルドの前に必ず `npm run css` か `npm run css:watch` を実行してください。

付属の CSV フォーマットは Rust のコードではなく `formats/import_formats.json` と `formats/export_formats.json` に書かれています。ビルド時にバイナリへ埋め込まれ、実行時に設定フォルダへ `csv_formats.json` / `csv_export_formats.json` として書き出されます（利用者はそのファイルを編集します）。これらの JSON が壊れているとテストが失敗します。

### 配布物の作成

```sh
npm ci && npm run css
dx bundle --desktop --release --out-dir dist
```

`dist/` に、その OS 用のインストーラが出力されます。

## リリース手順

`v*` 形式のタグを push すると、GitHub Actions（[`.github/workflows/release.yml`](.github/workflows/release.yml)）が Windows / Linux / macOS 用の配布物をビルドし、GitHub Release を作成します。

```sh
# Cargo.toml の version を更新してから
git tag v0.1.0
git push origin v0.1.0
```

Actions タブから手動で実行（workflow_dispatch）することもできます。その場合、リリースは作成されず、ビルドした配布物は Artifacts としてダウンロードできます。
